# 日本动漫模式

## 一键生成

1. 选择“日本动漫（日→中）”。默认建议本地 `small` 识别，已有 `base` 更快；模型需要时显式下载并校验。
2. 选择已保存的 API 方案和作品。先填好默认设置再导入，或导入后修改设置并“应用设置到选中”。
3. 可选片段；默认全片。点击“开始选中”或“开始全部”，确认后才识别、翻译和导出。

日语优先使用手动指定的 SRT，其次同名 `.ja.srt`，否则识别音频。不自动把未注明语言的同名 `.srt` 当日文。默认 UTF-8 / UTF-8 BOM，旧日文文件可在“原文字幕”选择 CP932。

输出包含 `ja.original.srt`（识别或导入原文）、`ja.srt`、`zh.srt`、`bilingual.srt`、ASS 和 MP4。原画面不裁切、不缩放，窄字幕带中文在上、日文在下；长句分页。

## 作品与人物译名

打开“作品与译名表”，填写作品名、日文原名、假名读音、别名、中文译名和可选备注。别名用 `|` 分隔。

正式处理不要求逐项人工确认：API 从本次全部原文自动选择固定中文名，自动约定与人工指定分别标识，不代表官方译名。同一作品的自动表保存在本地并用于后续任务；未选作品则按同一视频保存。完整敬称按固定规则生成，已指定完整称呼优先。任务开始后的有效名称表冻结在 `effective-names.json`，恢复任务保持原表。

如需人工覆盖，可填写条目、勾选确认并保存作品。手动编辑器的待确认候选不自动启用；正式处理的自动表与这个可选编辑流程独立。

自动生成或复用的译名会先检查说明性文字，例如“姐姐（称呼）”“小春（音译）”，识别出的说明移入条目备注，字幕只使用译名。正常别名括注（如“莉莉（Lily）”）和人工明确指定的目标不被静默改写。相同原文、模型和上下文的旧缓存可以定向清理；修改只作用于原文确实匹配到该名称的字幕，记录保存在本地工程，不为这类备注修正重复付费。

原名和读音只辅助识别，不能保证识别正确；中文译名和关系备注约束 API 翻译。默认自然中文，敬称不机械全部音译；自定称呼可写在备注。

## 先校对再翻译

选择待开始视频并点击“先识别 / 校对”。此时不调用翻译服务；完成后进入待校对，不阻塞其他已批准任务。

打开“校对原文 / 继续翻译”，修改台词和时间轴并保存。原始识别稿保留；校对稿从本次片段 00:00 计时。窗口会载入此任务设置，继续时使用主界面当前 API 方案及作品资料，片段范围保留。

“AI 起草候选”需要单独确认 API 调用，只分析前 100 条、最多 6000 字台词。生成的名字或译名可能猜错，不代表官方译名；必须逐条确认并保存作品后才生效。

## 路线及质量边界

- API：携带前后各两条只读上下文和精简摘要。匹配到的人名、别名、完整称呼先保护为标记，再严格还原到固定中文；原稿明确标出的说话人标签由程序保留，不推断新说话人。数量、编号和标记校验失败不会自动重发付费请求。
- 必应 / Google：复用固定表并保护译名；无现成表时保留识别出的人名原文作为统一写法，不暗中调用 API。不支持人物关系、语气等提示词控制。
- Argos：当前只有英中离线模型，动漫模式不可选，不自动切换付费服务。

“译名检查”显示本次固定表及可疑条目。结构保护保证匹配到的名称还原一致；未登记或未匹配的人物、代词指代、转写错误仍是质量边界。不会在中文译文中全局替换普通词，没有告警也不代表翻译完全正确。

日语识别使用独立语音区间和词级时间戳，避免跨长停顿粘连。背景歌曲、吼叫、多人重叠、低音质和陌生名字仍会导致误识别，重要内容先校对原文。不要把噪声、片头歌曲的识别结果当作正确对白。

首版不处理内封字幕、画面文字 OCR、歌词特效、声纹识别或配音。作品资料和所有真实验收素材不进入公开源码包。

## 可选自动精修（1.9.4）

主界面选择 API 方案后可开启，默认关闭。沿用当前模型，在翻译后以日文原句校对已有中文，不重新翻译有效缓存。名称与称呼保持固定，检测到名称改变、说话人标签改变或“（称呼）”等备注时保留原译，不追加付费重试。更多设置中的“翻译与精修”页包含全局理解和省用量选项；详细修改从“更多操作 → 校对与检查 → 查看精修修改”查看。自动精修可能有误，仍需结合原片判断。
