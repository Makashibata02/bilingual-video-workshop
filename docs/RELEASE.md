# 开源准备与发布检查

当前只准备源码，不自动创建仓库、推送、发布 Release 或上传任何文件。

## 首次上传

推荐仓库名 `bilingual-video-workshop`，简介“Windows 本地英中 / 日中双语字幕工坊：视频下载、选段、翻译、固定译名、可选自动精修与窄字幕带导出”。

本地整理时，使用公开白名单建立独立的上传源码目录；该目录可以初始化本地 Git 并暂存公开文件，但不创建远程仓库、不配置远程地址、不写入提交作者身份。不要把含程序、视频和个人资料的原工作目录直接设为远程仓库根目录。

首次提交前再次检查暂存区，并选择准备公开的 Git 作者名称及邮箱；如需隐藏个人邮箱，使用账户提供的 noreply 邮箱。可使用 GitHub Desktop 将独立源码目录作为现有本地仓库打开，审核改动后再创建远程仓库和发布。网页上传时上传源码文件及隐藏配置目录，不要把 ZIP 作为唯一的仓库内容。

首发仅含源码。自动精修已做有限真实字幕抽测，不能称为整集人工校译通过；CI 工作流在远程首次执行前也不能称为 GitHub Actions 已通过。

## 源码

1. 结束必要的功能修改，核对 README 和版本。
2. 运行 `python scripts/run_tests.py`。
3. 运行 `python scripts/install_gitleaks.py` 安装校验固定版本的扫描器。
4. 运行 `python scripts/check_public.py --gitleaks`，查看 `.local/reports` 中的结果。
5. 人工审阅 `scripts/public-files.json`。公开文件应与此列表一致。
6. 运行 `python scripts/export_source.py`，再次检查生成的源码 ZIP 和 SHA256SUMS。
7. 新增或修改文件后重新执行，不复用之前的通过结论。

不要上传整个项目工作目录。`.gitignore` 不会自动从历史记录删除曾经提交的文件，也无法阻止 `git add -f`；钩子和 CI 用于补充检查。

Git 仓库建立后，用 `python scripts/check_public.py --staged --gitleaks` 检查暂存内容。初次提交前，核对作者身份和准备公开的个人资料。当前不创建任何含个人身份的提交。

## 可执行程序

本次源码 ZIP 不包含可执行程序或模型。未来要发布 Windows 便携包，应在干净的官方 Python 环境重新构建，独立扫描打包结果，检查编译产物中的路径、证书、配置和日志，并补齐模型、FFmpeg 和其他依赖的许可材料。

重新构建不等于已经完成许可与隐私验收；当前本机旧程序不能直接压缩作为公开发行包。

本机测试包使用的构建解释器可能自带额外的 SSL 不信任证书安全策略数据，运行时必须保留其既有安全校验。此类构建环境文件不进入公开源码包；公开二进制须用干净的官方 Python 重新构建，不将本机测试包作为公开发行包，也不通过关闭 TLS 校验解决联网问题。
